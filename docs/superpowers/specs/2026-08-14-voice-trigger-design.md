# voice-trigger 設計書

## 目的

PipeWire/PulseAudio 環境で、舌打ちなどの短い音を検出し、それをトリガーに任意のコマンドを実行する CLI アプリケーション。

## 前提・非対象

- 対応OS: Linux (PipeWire の pulse 互換レイヤー、または PulseAudio がインストールされていること)。
- 音声認識・機械学習によるモデルは使用しない。振幅ベースの単純なオンセット検出のみ。
- 常駐(daemon)化・自動起動の仕組み(systemd unit ファイルなど)は本体に含めない。必要なら利用者が `--loop` と外部のプロセス管理(systemd `Restart=always` など)を組み合わせる。

## アーキテクチャ

3モジュールに分離する。

- **`audio.py`** — `parec` (PulseAudio互換コマンド。PipeWireのpulse互換レイヤーでも動作する) をサブプロセスとして起動し、生PCM (16kHz, mono, s16le) を短いチャンク単位(20ms程度)でイテレータとして返す。I/O専任でロジックを持たない。
- **`detector.py`** — 音声I/Oを持たない純粋なステートマシン `OnsetDetector`。チャンクごとのピーク振幅(`array('h', chunk)` から算出、絶対値の最大を 32768 で正規化)を計算し、閾値超えの立ち上がりエッジと経過時間を見てトリガー判定する。numpy 等の追加依存は使わず標準ライブラリの `array` モジュールのみで実装し、依存ゼロを維持する。音声I/Oと分離しているため、合成サンプル配列だけで単体テスト可能。
- **`cli.py`** — `audio.py` と `detector.py` を繋ぎ、サブコマンドごとの振る舞い(後述)を実装する。トリガー時のコマンド実行は `subprocess.Popen` (シェルを介さず argv リストのまま渡す。インジェクション対策・クォート不要)。

## CLI インターフェース

`argparse` の subparsers で `run` / `monitor` を分離する。各サブコマンドは自分に必要な引数だけを持つ。

```
voice-trigger run [--source SOURCE] [--threshold 0.3] [--cooldown 0.5] [--timeout SEC] [--loop] [-- COMMAND [ARGS...]]
voice-trigger monitor [--source SOURCE] [--threshold 0.3]
voice-trigger sources
```

共通オプション:

- `--source`: PulseAudio/PipeWire のソース名。省略時はデフォルト入力デバイス。
- `--threshold`: 0.0〜1.0 の正規化ピーク振幅閾値。デフォルト `0.3`。環境やマイクによって最適値は変わるため、`monitor` サブコマンドで実測して調整する運用を前提とする。

`run` 固有オプション:

- `COMMAND [ARGS...]`: `--` 以降をそのまま argv リストとして受け取る。**省略可能。** 省略時はコマンドを実行せず、検知した/しなかったという事実だけを終了コードで表現する(シェルスクリプトのゲートとして使える)。
- `--cooldown`: トリガー後の不感時間(秒)。1回の舌打ちで多重発火しないようにする。デフォルト `0.5`。
- `--timeout`: ワンショット待機時のタイムアウト秒数。省略時は無期限待機。`--loop` と同時指定はエラー。
- `--loop`: 指定すると終了せず、検知のたびに COMMAND を実行し続ける(COMMAND省略時は検知ログのみ出力)。停止は SIGINT/SIGTERM のみ。

### `run` の終了動作

- **デフォルト(`--loop` なし)はワンショット**: 1回検知したら (COMMANDがあれば実行して) 終了コード 0 で終わる。`--timeout` 秒以内に検知できなければ終了コード非0 (例: 1) で終わる。
- **`--loop` 指定時**: 終了せず、検知のたびに COMMAND 実行を繰り返す。`--timeout` は無視される(`--loop` と `--timeout` の同時指定はエラーとして起動時に弾く)。連続検知させたい用途はこちらを使う。停止は SIGINT/SIGTERM。

### `monitor` の動作

コマンド実行を一切行わず、`--cooldown` の概念も持たない。チャンクごとの現在のピークレベルと閾値超え判定を標準出力に流し続ける、`--threshold` 調整専用のモード。

### `sources` の動作

`pactl list short sources` を実行し、その結果からソース名の列だけを抽出して1行ずつ標準出力に表示する。ここで表示された名前をそのまま `--source` に渡せる。

## データフロー

1. `audio.py` が `parec` を起動し、PCMチャンクを順次生成。
2. `cli.py` が各チャンクを `OnsetDetector.process(chunk, now)` に渡す。
3. `run` モード: `True` (トリガー) が返ったら COMMAND を `Popen` で起動(完了を待たず、次のチャンク処理を継続)。ワンショットなら直後にプロセス終了処理へ。`--loop` ならループ継続。
4. `monitor` モード: 毎チャンクのレベルと閾値超え判定を標準出力に表示するのみ。

## エラーハンドリング

- `parec` が見つからない、または異常終了した場合: エラーメッセージを表示して非ゼロ終了。
- SIGINT/SIGTERM 受信時: `parec` 子プロセスを終了させてからプロセスを終了する。
- `--loop` と `--timeout` の同時指定: 起動時に argparse レベルでエラーにする。

## テスト

- `OnsetDetector` は合成PCM配列を入力にした純粋な単体テストでカバーする(閾値・クールダウンの境界条件、立ち上がりエッジの判定など)。
- `audio.py` はサブプロセス起動の薄いラッパーに留め、実機の `parec` を要する統合テストは対象外とする。コマンド組み立て(引数の並び)部分のみ単体テストする。
- `sources` サブコマンドの `pactl list short sources` 出力からソース名を抽出するパース処理は、サンプル出力を入力にした単体テストでカバーする。
- CLI の引数パース(`--loop` と `--timeout` の排他など)は argparse レベルの単体テストでカバーする。
